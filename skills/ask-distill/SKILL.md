# ask-distill

`add_ask`が返す`similar_asks`（近傍askの裁定内容=answer_body込み）を読み、同型の問いが繰り返され裁定が一貫していると判断した場合に、判例（answer_bodyの集積）をまとめてメタask（`kind="meta"`）を起票する。メタaskは「この型の問いは今後、判例に従って自己裁定してよいか」を人間に問う一段上の問いであり、一般化ルールの発効そのものではない（発効は人間のメタask裁定を待つ）。

## 発動契機

`add_ask`のレスポンスを受け取った直後、`similar_asks`に含まれる過去askの`answer_body`を見て、以下の両方に該当すると判断したとき:

- 同型の問い（表現は異なっても実質同じ判断軸）が2件以上（`similar_asks`内、または過去の`get_asks`結果と合わせて）繰り返されている
- それらの裁定（`answer_body`）が一貫している（毎回同じ方針で答えられている）

裁定が割れている・件数が少ない（同型が初出）・`similar_asks`が空、のいずれかに該当する場合は発動しない。

## 手順

1. **トリガーaskのblocksを確認する**: 今まさに起票したask（直前の`add_ask`呼び出しの返り値の`id`）について、その`add_ask`呼び出しに渡した`blocks`引数の値をそのまま使う（改めて`get_asks`等で取り直さない）。
2. **判例を集約する**: `similar_asks`から、同一裁定（`answer_body`）が繰り返されている件数と内容をまとめる（何件、どんな裁定だったか）。
3. **メタaskを起票する**: 以下の形で`add_ask`を呼ぶ。
   - `question`: `"この型の問いは今後、判例（N件: 裁定内容の要約）に従って自己裁定してよいか？"`
   - `context`: 集約した判例の詳細（各askの問いと裁定の対応がわかる形で）
   - `blocks`: 手順1で確認したトリガーaskのblocksをそのまま引き継ぐ（新設のactivityは作らない）
   - `kind`: `"meta"`（必須）
   - `tags`: トリガーaskと同じ`domain:`タグ + `"meta-ask"`
4. **トリガーになった元のaskはopenのまま残す**: withdrawしない。「今回この場で自己裁定できるか」はルール3の別判断であり、このskillのスコープ外。

## 注意

- メタaskの裁定（人間の回答）が「自己裁定してよい」であっても、一般化ルールが自動発効するわけではない。発効は人間のメタask裁定でのみ行われ、機械もLLMも勝手に発効しない（`RULES`の「## Asks（判断委譲）」節参照）。
- メタask自体も答え待ちの間、渡した`blocks`のactivityを止める。トリガーaskと同じblocksを渡すため、二重に答え待ちが積まれる形になるが、これは意図的（両方とも同じactivityの進行を実際に止めている判断待ちのため）。
