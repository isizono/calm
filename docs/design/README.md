本ディレクトリは、実装前の詳細設計（レビュー用の設計提案）を置く場所である。`docs/architecture/` と `docs/spec/` が「実装済みのものの写し取り」であるのに対し、ここは「これから作るものの仕様」を置く。性質上ある時点のスナップショットであり、ccm-doc-sync マーカーは付けない（鮮度チェックの対象外）。実装が完了した設計は、必要に応じて `docs/architecture/` / `docs/spec/` 側へ写し取ったうえで、本ディレクトリから削除してよい。

## 決定論的周辺構造 設計群（2026-07）

作業中盤の自発的リコール不在への対処として運用が決まった確率的な3層（計測前倒し / check_in督促nudge / 記録=クエリ添付）の周辺に、機構で保証できる決定論的構造を足す設計群である。検討会（2026-07-09）でユーザー承認済みの決定を詳細設計に落としたもの。

### 共通の設計フレーム

決定論は認知（Claudeが気づく・読む・活かす）には触れられないが、状態は保証できる。保証できる面は4つ:

1. **DBの状態** — 何が現役で何が退役か、総量が予算内か
2. **コンテキストの内容** — 何が確実に載るか、欠けたら欠けたと分かるか
3. **カウンタ** — 何回提示され、何回追随されたか
4. **行動の発生** — 必要なツール呼び出しが行われたか

「思い出させる」は保証不可、「確実に載せる・数える・痩せさせる」までが保証範囲。発見は確率的にしかできないが、一度確認された発見の再発見は決定論化できる（relation固定）。

### 依存関係

- **退役マーク**: 独立。最初に実装できる
- **追随カウンタ**: 記録=クエリ添付（未実装の後続マイルストーン）と同時に実装する。単独先行しない
- **配送網羅保証**: check_in側はcheck_in内部リライト（別途詳細設計進行中）への要件。SessionStart側は隣接する採用済み設計（注入コンポジタのSection宣言）が実装を担う
- **relation固定**: 記録=クエリ添付+追随カウンタの実装後
- **聞き返し検出**: sync-memoryスキルの構成に依存。実装前に進行中の記録系skill強化作業との衝突確認を行う
